

## 通俗讲解：发现的问题和修复方案

---

### 一、安全问题（最严重）

**问题描述**：你的系统像一栋公寓楼，但有 6 套房间的门锁坏了——任何人可以不证明身份就随意进出这些房间（API），查看、修改甚至删除别人的数据。

**具体表现**：
- 攻击者只需要在请求体里随便填一个用户ID，就能冒充别人操作他的回忆录、章节、家庭成员等信息
- 所有 API 没有任何请求频率限制，攻击者可以一秒内发送几万次请求把服务器打瘫
- 服务器崩溃时（比如突然断电），数据文件会直接损坏，因为写入是"直接覆盖"而非"先写副本再替换"

**修复方案**：

1. **给所有房间装上真正的门锁**：所有 API 现在都要求先验证 JWT token（一种签名令牌），没有有效 token 的人一律拒绝访问
2. **安装限流器**：每个 IP/用户每分钟最多请求 30 次，超过直接拒绝并告知"请稍后再试"
3. **安全写入**：数据写入改为"先写到一个临时文件，写完确认无误后，再替换原文件"，即使中途崩溃也不会损坏原数据

---

### 二、业务逻辑 Bug（影响功能正确性）

**问题描述**：几个核心功能的算法写错了，导致功能不正常。

**具体表现**：

1. **追问模板搞错了**：系统应该根据话题类型随机选一个追问模板，但 `place` 相关的模板被错误地写成了对象而不是列表，导致追问逻辑直接崩溃
2. **困难阶段没设敏感度**：系统有多个访谈阶段，其中"困难与转折"阶段需要特别小心处理（老人可能不愿回忆往事），但这个阶段的敏感度设置漏了，导致追问语气可能不合适
3. **人名识别正则写错**：代码里有 `/[老师|同学|同事]/g` 这样的写法——在正则里 `[]` 表示"匹配其中任意一个字符"，而 `|` 在 `[]` 里会被当作普通字面量，所以实际上它匹配的是"老"|"师"|"同"|"学"……等单字，而不是"老师""同学"等词组

**修复方案**：分别修正了追问模板结构、补充困难阶段敏感度、修复正则表达式

---

### 三、内存泄漏（影响长期运行稳定性）

**问题描述**：前端有一个定时监听器在组件卸载时没有正确关闭，导致每次进入页面都创建一个新的监听器，旧的不关闭，浏览器内存会越用越大，最终变卡变慢。

**修复方案**：在 React 组件卸载时（`useEffect` 的 return 清理函数）正确调用 `recognition.abort()` 关闭监听器。

---

### 四、并发竞态条件（影响多用户场景）

**问题描述**：当前端多个请求同时发现 token 过期时，会同时去刷新 token，形成"多线程抢锁"的情况——可能互相覆盖 token，导致越刷新越乱。

**修复方案**：引入一个"刷新锁"，同一时间只允许一个刷新请求进行，其他请求等待第一个完成后再复用结果。

---

### 五、输入验证缺失（影响系统健壮性）

**问题描述**：用户可以往 API 发送任意格式的数据（比如超长字符串、空值、非法格式），系统来者不拒，容易引发报错甚至崩溃。

**修复方案**：为所有 API 添加了 Zod 验证（一种结构化验证库），比如：
- "标题不能为空，最长 200 字符"
- "邮箱必须是正确的 email 格式"
- "ID 必须是 UUID 格式"

---

### 六、日志不规范（影响排查效率）

**问题描述**：代码里到处散布 `console.error()` 和 `console.log()`，这些日志会直接暴露到浏览器控制台，生产环境里既不安全也难以统一管理。

**修复方案**：创建了统一的 `client-logger.ts`，将所有 `console` 调用替换为结构化日志，支持分类（debug/info/warn/error）并自动带上时间戳。

---

### 七、列表查询无分页（影响大数据量性能）

**问题描述**：当用户有很多记忆卡片、回忆录草稿时，`getUserMemoryCards()` 这样的函数会一次把全部数据从文件读进内存，数据量大了会很慢。

**修复方案**：所有列表查询函数现在支持分页参数，返回 `{ items, total, page, pageSize, totalPages }` 的结构，默认每页 20 条。

---

### 总结

这次修复覆盖了 **4 个安全漏洞 + 3 个业务 Bug + 2 个稳定性问题 + 2 个代码质量改进 + 1 个性能优化**，共 15 项。TypeScript 编译已全部通过，代码现在更安全、更稳定、更规范。
